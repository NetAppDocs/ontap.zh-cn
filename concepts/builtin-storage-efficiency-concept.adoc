= 了解ONTAP专用卸载处理器的存储效率
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
专用卸载处理器存储效率执行连续物理块的顺序打包，并使用专用卸载处理器进行 32k 数据压缩。通过 32k 压缩，可在聚合级别实现空间节约，这与使用 8k 自适应压缩的系统不同，后者在卷级别实现空间节约。使用专用卸载处理器存储效率的系统不使用温度敏感存储效率（TSSE），这意味着压缩不是基于热数据或冷数据。这样可以立即节省空间，而不会对性能产生任何影响。

专用卸载处理器存储效率需要 QuickAssist 技术（QAT）支持，并且在以下系统上受支持。默认情况下，它在列出的 AFF 系统上处于启用状态。


NOTE: AFF A20 系统不支持专用卸载处理器存储效率。对于 AFF A20 系统，使用 SnapMirror 技术迁移的数据将使用主 CPU 自动转换为 32k 内联压缩。

* AFF A 系列系统：AFF A1K、AFF A90、AFF A70、AFF A50、AFF A30
* AFF C 系列系统：AFF C80、AFF C60、AFF C30
* FAS 系统：FAS90、FAS70、FAS50


ASA r2 系统和 AFX 系统还支持 QAT 以及默认启用专用卸载处理器存储效率。

* ASA r2 系统为仅限 SAN 的客户提供简化的 ONTAP 体验。link:https://docs.netapp.com/us-en/asa-r2/get-started/learn-about.html["详细了解 ASA r2 系统"]。
* AFX 系统提供专门针对高性能 NAS 和 S3 客户独特需求的 ONTAP 解决方案link:https://docs.netapp.com/us-en/ontap-afx/get-started/ontap-afx-storage.html["详细了解 AFX 系统"]。


对于以下系统，存储效率会自动启用，无需配置。这适用于所有新创建的精简配置卷和现有数据，包括从其他系统移动的卷。无论空间保证设置如何，都会启用重复数据删除。压缩和数据压缩都要求将空间保证设置为无。使用卷移动或 SnapMirror 技术迁移的数据会自动转换为 32k 内联压缩。

* AFF A 系列系统：AFF A1K、AFF A90、AFF A70、AFF A50、AFF A30
* AFF C 系列系统：AFF C80、AFF C60、AFF C30


对于以下系统，默认情况下，仅在升级到 ONTAP 9.15.1 或更高版本之前已启用存储效率的现有精简配置卷上启用存储效率。您可以使用 ONTAP CLI 或 ONTAP REST API 在新创建的卷上启用存储效率。只有在原始平台上启用了压缩时，使用卷移动或 SnapMirror 技术迁移的数据才会转换为 32k 内联压缩。

* FAS90
* FAS70
* FAS50


有关将控制器升级到受支持系统之一的信息，请参见 https://docs.netapp.com/us-en/ontap-systems-upgrade/choose_controller_upgrade_procedure.html["ONTAP 硬件升级文档"^]。

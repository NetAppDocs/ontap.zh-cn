= 了解 NetApp 使用 ONTAP Vscan 进行病毒扫描
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Vscan 是一种防病毒扫描解决方案，可让您保护数据免受病毒或其他恶意代码的侵害。它将合作伙伴提供的防病毒软件与 ONTAP 功能相结合，为您提供管理文件扫描所需的灵活性。



[[how-virus-scanning-works]]
== 病毒扫描的工作原理

存储系统将扫描操作卸载到托管第三方供应商提供的防病毒软件的外部服务器。

根据活动扫描模式、当客户端按计划或立即(按需)通过SMB (实时)访问文件或访问特定位置的文件时、ONTAP会发送扫描请求。

* 当客户端通过 SMB 打开，读取，重命名或关闭文件时，您可以使用 _on-access scanning-来 检查病毒。文件操作将暂停、直到外部服务器报告文件的扫描状态为止。如果文件已扫描，则 ONTAP 允许执行文件操作。否则，它将从服务器请求扫描。
+
NFS 不支持实时扫描。

* 您可以使用 _on-Demand scanning-立即 或按计划检查文件中的病毒。我们建议按需扫描只在非高峰时段运行、以避免现有AV基础架构过载、而现有AV基础架构的规模通常适合实时扫描。外部服务器会更新已检查文件的扫描状态、以便通过SMB减少文件访问延迟。如果进行了文件修改或软件版本更新、则会从外部服务器请求新的文件扫描。
+
您可以对 SVM 命名空间中的任何路径使用按需扫描，即使是仅通过 NFS 导出的卷也是如此。



通常、您会在SVM上同时启用实时和按需扫描模式。在任一模式下、防病毒软件都会根据您的软件设置对受感染的文件采取补救措施。

ONTAP 防病毒连接器由 NetApp 提供并安装在外部服务器上，用于处理存储系统与防病毒软件之间的通信。从 ONTAP 9.20.1 开始，ONTAP 支持基于互联网内容适配协议（ICAP）的扫描路径，从而无需使用防病毒连接器。每个 SVM 只能使用 ICAP 或防病毒连接器，不能同时使用两者。


NOTE: 基于 ICAP 的 Vscan 仅支持访问时扫描。



[[icap-based-vscan-compared-with-the-antivirus-connector]]
== 基于 ICAP 的 Vscan 与 Antivirus Connector 的比较

下表总结了 Antivirus Connector 和基于 ICAP 的 Vscan 之间的差异：

[cols="30,35,35"]
|===


| 功能 | Antivirus Connector | 基于 ICAP 的 Vscan 


| 组件 | Windows 服务器上安装的 ONTAP 防病毒连接器 | 不需要；ONTAP 直接连接到扫描引擎 


| 通信协议 | SMB 命名管道和 MS-RPC | 基于 TCP 的 ICAP 


| 基础架构 | 专用 Vscan 连接管理器 | FPolicy 共享内存通知管道 


| 支持的扫描引擎操作系统 | 仅限 Windows | Windows 和 Linux 


| 可扩展性 | 每个 Antivirus Connector 实例限制为 400 个 LIF 连接 | 利用 FPolicy 连接池实现更高的可扩展性 


| 发现机制 | 基于轮询的 SVM 和 LIF 发现 | 通过 FPolicy 进行事件驱动连接管理 
|===

= ONTAP LIF与端口类型的兼容性
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
LIF 可具有不同的特性以支持不同的端口类型。LIF 可托管在 IPspace 中的物理或逻辑端口上。每个端口仅与一个 IPspace 相关联。


NOTE: 如果在同一子网中配置了集群间和管理 LIF ，则管理流量可能会被外部防火墙阻止，并且 AutoSupport 和 NTP 连接可能会失败。您可以通过运行来恢复系统 `network interface modify -vserver _vserver name_ -lif _intercluster LIF_ -status-admin up|down` 命令切换集群间LIF。但是，您应在不同子网中设置集群间 LIF 和管理 LIF ，以避免使用此问题描述。

下表总结了 LIF 类型、其兼容端口类型及其故障转移或迁移行为。

[cols="30,70"]
|===


| LIF | Description 


| 集群 LIF  a| 
用于在集群中的节点之间传输集群内流量的 LIF。

* 集群 LIF 必须始终在集群端口上创建。
* 集群 LIF 可以在同一节点上的集群端口之间进行故障转移，但不能迁移或故障转移到远程节点。当新节点加入集群时，IP 地址会自动生成。但是，如果要将 IP 地址手动分配给集群 LIF，则必须确保新 IP 地址与现有集群 LIF 位于相同的子网范围内。




| 集群管理 LIF  a| 
为整个集群提供单一管理界面的 LIF。

* 集群管理 LIF 可以故障转移到集群中的任何节点。它不能故障转移到集群或集群间端口。




| 数据 LIF  a| 
与存储虚拟机（SVM）关联并用于与客户端通信的 LIF。

* 每个 SVM 都与特定的 IPspace 相关联。数据 SVM 通常位于“Default” IPspace 中，但不一定。
* 您可以在一个端口上托管多个数据 LIF。这些数据 LIF 可以在整个集群中迁移或故障转移。您可以通过将数据 LIF 的防火墙策略修改为 mgmt，将其修改为用作 SVM 管理 LIF。
* 与 NIS、LDAP、Active Directory、WINS 和 DNS 服务器建立的会话使用数据 LIF。




| 集群间 LIF  a| 
用于跨集群通信、备份和复制的 LIF。

* 在建立集群对等关系之前，必须在集群中的每个节点上创建集群间 LIF。这些 LIF 只能故障转移到同一节点中的端口。它们无法迁移或故障转移到集群中的其他节点。




| 节点管理 LIF  a| 
提供用于管理集群中特定节点的专用 IP 地址的 LIF。

* 节点管理 LIF 是在创建或加入集群时创建的。这些 LIF 用于系统维护，例如，当节点无法从集群访问时。




| SVM 管理 LIF  a| 
提供到 SVM 的管理连接的 LIF，支持该 SVM 的管理操作（通常通过端口 443）和管理相关服务。

* 每个 SVM 都与特定的 IPspace 相关联。
* LIF 可以根据故障转移策略迁移或故障转移到另一个节点或端口。
* 您可以在一个端口上托管多个 SVM 管理 LIF。
* 当您在多租户环境中托管时，SVM 管理 LIF 非常有用。




| VIP LIF  a| 
虚拟 IP （VIP） LIF 是在 VIP 端口上创建的任何数据 LIF。

如需了解更多信息，请参见 link:../networking/configure_virtual_ip_vip_lifs.html["配置虚拟 IP （ VIP ） LIF"]。

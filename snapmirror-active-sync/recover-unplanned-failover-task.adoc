= 从自动的、计划外的ONTAP集群故障转移操作中恢复
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
当主集群关闭或隔离时，会发生自动计划外故障转移 (AUFO) 操作。SnapMirror 活动同步会检测到此类故障，并启动自动计划外故障转移到辅助集群。辅助集群将转换为主集群（首选集群），并开始为客户端提供服务。请注意，故障检测和故障转移处理只能在 ONTAP Mediator 的帮助下执行。


NOTE: 在自动计划外故障转移之后，请务必重新扫描主机路径，以免丢失 I/O 路径。



[[reestablish-the-protection-relationship-after-an-unplanned-failover]]
== 在计划外故障转移后重新建立保护关系

一旦原始主集群（例如集群 A）恢复，SnapMirror 活动同步将自动反向建立保护。如果要恢复原始状态，使集群 A 成为主要的首选集群，则可以通过使用 System Manager 或 ONTAP CLI 启动计划的故障转移操作来执行手动故障恢复。

[role="tabbed-block"]
====
.System Manager
--
.步骤

IMPORTANT: 从 ONTAP 9.8 到 ONTAP 9.14.1，SnapMirror 主动同步称为 SnapMirror 业务连续性（SM-BC）。

. 导航到*保护>关系*并等待关系状态显示“InSync”。
. 要在原始源集群上执行故障回复和恢复操作，请单击 image:icon_kabob.gif["菜单选项图标"] 并选择 *Failover*。


--
.命令行界面
--
您可以使用监控自动计划外故障转移的状态 `snapmirror failover show` 命令：

例如：

....
ClusterB::> snapmirror failover show -instance
Start Time: 9/23/2020 22:03:29
         Source Path: vs1:/cg/scg3
    Destination Path: vs3:/cg/dcg3
     Failover Status: completed
        Error Reason:
            End Time: 9/23/2020 22:03:30
Primary Data Cluster: cluster-2
Last Progress Update: -
       Failover Type: unplanned
  Error Reason codes: -
....
可以使用原始主集群上的  `snapmirror show` 命令监视反向保护关系的状态。

例如：

....
ClusterA::> snapmirror show
                                                                               Progress
Source             Destination  Mirror        Relationship   Total             Last
Path         Type  Path         State         Status         Progress  Healthy Updated
-----------  ----  ------------ -------       -------------- --------- ------- --------
vs3:/cg/dcg3 XDP   vs1:/cg/scg3 Snapmirrored  InSync          -         true    -
....
您可以使用  `snapmirror failover start` 命令对原始主集群执行故障回复。

例如：

....
ClusterA::> snapmirror failover start -destination-path vs1:/cg/scg3
....
请参见 link:https://docs.netapp.com/us-en/ontap-ems-9131/smbc-aufo-events.html["EMS参考"^] 了解事件消息和更正操作。

--
====


[[resume-protection-in-a-fan-out-configuration-after-failover]]
== 故障转移后、在扇出配置中恢复保护

从 ONTAP 9.15.1 开始，SnapMirror 活动同步支持在 SAN 关系中的故障转移事件后在扇出支路中自动重新配置。在 NAS 配置中，必须在 SnapMirror 活动同步故障转移后手动重新配置保护关系。异步扇出分支可以是一致性组关系或独立的卷关系。有关详细信息，请参见link:interoperability-reference.html#fan-out-configurations["扇出配置"]。

如果您使用的是ONTAP 9.14.1或更早版本、并且在SnapMirror活动同步关系中的二级集群上发生故障转移、则SnapMirror异步目标运行状况会不正常。您必须通过删除并重新创建与SnapMirror异步端点的关系来手动还原保护。

.步骤
. 验证故障转移是否已成功完成：
`snapmirror failover show`
. 在SnapMirror异步端点上、删除扇出端点：
`snapmirror delete -destination-path _destination_path_`
. 在第三个站点上、在新的SnapMirror活动同步主卷和异步扇出目标卷之间创建SnapMirror异步关系：
`snapmirror create -source-path _source_path_ -destination-path _destination_path_ -policy MirrorAllSnapshots -schedule _schedule_`
. 重新同步此关系：
`snapmirror resync -destination-path _destination_path_`
. 验证关系状态和运行状况：
`snapmirror show`

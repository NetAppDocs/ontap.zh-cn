= 了解使用 ONTAP 系统配置 FC 结构的最佳实践
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
遵循 FC 结构配置最佳实践可提高结构更改期间的主机和目标性能、可靠性和稳定性。

.推荐的 FC 结构配置最佳实践
* *单启动器/单目标（SI/ST）分区*
+
SI/ST 分区降低了交换矩阵更改期间的延迟峰值，消除了串扰，限制了注册状态更改通知（RSCN），简化了故障排除，并将路径计数保持在主机限制范围内。

+
** 主机影响：SI/ST 分区可确保可预测的 MPIO 行为、更快的发现速度以及更少的所有路径瘫痪（APD）/永久设备丢失（PDL）事件。
** 目标影响：SI/ST 分区可确保更少的登录/注销事件和稳定的 FC 会话。


* *使用目标 LIF WWPN（非物理端口）进行基于 WWPN 的分区*
+
基于 WWPN 的分区支持 LIF 移动性、接管/交回、无中断操作而无需重新分区，并防止维护期间的路径重置。

+
** 主机影响：基于 WWPN 的分区可确保在 LIF 移动或控制器故障转移期间不会丢失路径。
** 目标影响：基于 WWPN 的分区确保 ONTAP 可以透明地移动目标 LIF。


* *在所有 FC 交换机上启用 NPIV*
+
连接到结构的所有交换机必须支持 NPIV，并且必须启用 NPIV。ONTAP 使用 N_Port ID 虚拟化（NPIV）来呈现 FC 目标。如果没有它，目标 LIF 将无法正确登录。

+
** 主机影响：NPIV可防止间歇性路径丢失和设备丢失。
** 目标影响：NPIV 确保目标 LIF 可见性和稳定的 FC 登录。


* *完全隔离的双独立交换架构*
+
双独立交换矩阵由两个独立的物理交换机、电源和布线组成。交换矩阵 A 和交换矩阵 B 从不相互连接。每个交换矩阵都维护自己的 FC 名称服务器、区域集和域 ID。由于交换矩阵是完全隔离的，因此不存在单点故障。可以在一个交换矩阵上执行无中断维护，而另一个交换矩阵继续运行。

+
** 主机影响：在交换矩阵固件升级或故障期间，双独立交换矩阵支持连续 I/O。
** 目标影响：双独立结构在交换机问题期间保持冗余目标访问。


* *固定 FC 端口速度（避免自动协商）*
+
自动协商可能会延迟交换矩阵重建，导致速度不匹配，并导致重新收敛延迟和链路抖动。

+
** 主机影响：固定的 FC 端口速度会导致链路重置期间的中断窗口缩短。
** 目标影响：固定 FC 端口速度可使端口在节点或交换机事件发生后更快恢复运行。


* *严格遵守 NetApp 互操作性矩阵工具（IMT）验证的配置（HBA、驱动程序、固件、交换机）*
+
严格遵守在 https://mysupport.netapp.com/matrix["NetApp IMT"^]中验证的配置，可保持预期的延迟和吞吐量。

+
** 主机影响：使用 IMT 验证的配置可避免无法解释的 I/O 错误和超时。
** 目标影响：使用 IMT 验证的配置可防止协议级别的不兼容性。


* *主动监控 FC 错误计数器（CRC、同步丢失、RECV_ERROR）*
+
在 ONTAP 存储计数器检测到结构错误之前，结构错误通常显示为主机端延迟或 I/O 错误。主动监控 FC 错误计数可防止持续的延迟膨胀。

+
** 主机影响：主动监控可实现早期检测，并防止主机 I/O 重试和应用程序停顿。
** 目标影响：主动监控可避免将 Fabric 问题错误归因为存储问题。


* *避免交换机间链路（ISL）对 SAN 流量的超额订阅*
+
拥塞的 ISL 会导致信用匮乏和慢速消耗行为。

+
** 主机影响：避免 ISL 超额订阅可减少主机 I/O 等待时间和排队时间。
** 目标影响：避免 ISL 超额订阅可防止对 ONTAP FC 端口的背压。

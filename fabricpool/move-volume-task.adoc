= 将卷移动到启用了FabricPool的ONTAP本地层
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
link:../volumes/move-volume-task.html["卷移动"] 可无中断地将卷从一个 ONTAP 本地层（源）移动到另一个本地层（目标），最常用于硬件生命周期管理、集群扩展或负载平衡。将卷移动到启用了 FabricPool 的本地层时，了解移动操作如何影响分层数据和分层策略有助于避免不必要的网络流量和对象存储成本。

卷移动对本地层、连接的云层和卷分层策略所做的更改可能会对 FabricPool 功能产生重大影响。


NOTE: 在ONTAP 9.7之前的版本中、System Manager会使用术语_AGREL_来描述_local ti层_。无论您的ONTAP版本如何、ONTAP命令行界面都使用术语_AGREL_。要了解有关本地层的更多信息，请参见link:../disks-aggregates/index.html["磁盘和本地层"]。



[[destination-local-tier]]
== 目标本地层

如果卷移动的目标本地层没有附加的云层，则源卷中存储在云层上的数据将写入目标本地层。

从 ONTAP 9.8 开始，当卷启用了 link:determine-data-inactive-reporting-task.html["非活动数据报告"] 时，一旦数据被写入目标本地层，FabricPool 就会使用该卷的热图将冷数据排队以进行分层。

在 ONTAP 9.7 及更早版本中，将卷移动到另一个本地层会重置本地层上块的非活动期。例如，如果卷使用 Auto 卷分层策略，并且本地层上的数据已处于非活动状态 20 天但尚未分层，则卷移动会将该数据的温度重置为 0 天。



[[optimized-volume-moves]]
== 优化的卷移动

从 ONTAP 9.6 开始，如果卷移动的目标本地层使用与源本地层相同的存储桶，则存储在存储桶中的源卷上的数据不会移回本地层。分层数据保持静止，只有热数据需要从一个本地层移动到另一个本地层。这种优化的卷移动可显著提高网络效率。

例如，在 300TB 优化卷移动中，即使 300TB 冷数据从一个本地层移动到另一个本地层，该移动也不会触发对对象存储的 300TB 读取和 300TB 写入。

未经优化的卷移动会产生额外的网络和计算流量(读取/获取和写入/放置)、从而增加对ONTAP集群和对象存储的需求、并可能在分层到公共对象存储时增加成本。

[NOTE]
====
某些配置与优化的卷移动不兼容：

* 在卷移动期间更改分层策略
* 源和目标本地层使用不同的加密密钥
* FlexClone 卷
* FlexClone父卷
* MetroCluster (在ONTAP 9.8及更高版本中支持优化的卷移动)
* 未同步FabricPool镜像分段
* 卷从支持 QuickAssist 技术（QAT）的平台移动到不支持的平台


详细了解link:https://kb.netapp.com/on-prem/ontap/DP/SnapMirror/SnapMirror-KBs/How_do_platforms_supporting_QAT_or_zlib_compression_impact_SnapMirror_and_volume_move["QAT 如何影响卷移动"^]。

====
如果卷移动的目标本地层具有附加的云层，则存储在云层上的源卷上的数据将首先写入目标本地层上的本地层。然后，如果卷的分层策略允许，则将数据写入附加到目标本地层的云层。

首先将数据写入本地层可提高卷移动的性能并减少切换时间。如果在移动卷时未指定卷分层策略，则目标卷将使用源卷的分层策略。

如果在移动该卷时指定了其他分层策略，则将使用指定的分层策略创建目标卷，并且不会优化该卷的移动。



[[volume-metadata]]
=== 卷元数据

无论卷移动是否经过优化，ONTAP 都会存储大量有关所有数据（包括本地和分层数据）的元数据，包括其位置、存储效率、权限和使用模式。元数据始终保留在本地层，且不会被分层。当卷从一个本地层移动到另一个本地层时，此信息也需要移动到目标本地层。



[[duration]]
=== 持续时间

卷移动仍需要一段时间才能完成。预计优化的卷移动所需的时间与移动等量的非分层数据所需的时间大致相同。

此 `volume move show`命令报告的吞吐量表示本地更新的卷数据，而不是从云层移动的数据。


NOTE: 当卷处于 SVM DR 关系中时，源卷和目标卷必须使用相同的分层策略。

.步骤
. 使用 `volume move start`命令将卷从源本地层移动到目标本地层。


.移动卷的示例
以下示例将 `vs1` SVM 中名为 `myvol2`的卷移动到已启用 FabricPool 的本地层 `dest_FabricPool`。

[listing]
----
cluster1::> volume move start -vserver vs1 -volume myvol2
-destination-aggregate dest_FabricPool
----

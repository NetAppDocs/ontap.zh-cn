[[data-protection]]
== 数据保护

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirror 云支持就地还原至原始源卷]
 a| 
SnapMirror 云支持对 FlexVol 卷进行就地还原操作，使您能够直接将云快照还原到原始源卷。ONTAP 选择最新的公共快照并执行增量传输，从而缩短还原时间。



 a| 
xref:../snapmirror-active-sync/limits-reference.html[SnapMirror 活动同步对象限制增加]
 a| 
SnapMirror 活动同步将 SAN 和 NAS 配置中每个 HA 对支持的卷数量增加到 600 个。



 a| 
xref:../snaplock/snapshot-lock-concept.html[具有 SnapMirror 活动同步 NAS 的防篡改快照支持]
 a| 
ONTAP 增加了对 SnapMirror 活动同步 NAS FlexVol 卷的防篡改快照的支持。此增强功能允许客户将 SnapMirror 活动同步 NAS 可用性与不可变快照保护相结合。



 a| 
xref:../data-protection/modify-svm-dr-dest-vol-capacity-task.html[增强的 SVM 灾难恢复]
 a| 
ONTAP 通过允许使用标准管理员权限卷修改工作流在 SVM-DR 目标卷上修改选定的卷属性来增强 SVM 灾难恢复，从而减少了对支持辅助过程的需求。

ONTAP 还将可选的 SVM-DR 快速重新同步支持扩展到 FlexGroup 成分卷，帮助包含大型 FlexGroup 的 SVM 在 DR 演练、重新同步或反向重新同步工作流后更快地恢复到受保护状态。

有关详细信息，请参见 xref:../data-protection/resync-svm-destination-task.html[重新同步ONTAP SnapMirror目标SVM上的数据]。



 a| 
xref:../data-protection/configure-backend-fc-replication.html[通过 FC 进行 SnapMirror 复制的后端支持]
 a| 
您可以通过现有光纤通道 (FC) 结构配置后端 SnapMirror 异步复制以及适用于 SnapVault 的 SnapLock。

这允许复制流量完全在现有 SAN 基础架构内传输。在 ONTAP 9.20.1 之前，这些复制关系的流量仅通过群集间 IP 网络传输。



 a| 
xref:../consistency-groups/protect-task.html[从非 SnapLock 源一致性组复制到 SnapLock for SnapVault 目标一致性组]
 a| 
您可以从非 SnapLock 源一致性组复制到 SnapLock for SnapVault 目标一致性组。SnapLock for SnapVault 可防止意外或恶意删除已复制的一致性组。



 a| 
xref:../san-admin/fc-sp-3-security-support.html[使用 Broadcom 安全 HBA 进行 FC-SP-3 身份验证和加密]
 a| 
ONTAP 支持在采用 AFF 和 FAS 系统的 Broadcom 安全 HBA 上进行光纤通道安全协议 3 (FC-SP-3) 身份验证和加密。FC-SP-3 支持实现硬件级端到端加密和设备身份验证，以保护在 FC 和 NVMe/FC SAN 主机与 ONTAP 存储系统之间传输的数据，同时符合 T11 光纤通道安全标准。

加密已卸载，因此不会对您的存储系统造成性能影响。

[[fpolicy-enhancements]]
== FPolicy 增强功能

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-nfsv4-concept.html[NFS 4.2 的 FPolicy 支持]
 a| 
FPolicy 将文件访问监控扩展到 NFSv4.2，为使用最新 NFS 协议版本的环境启用审核、合规性和网络弹性工作流程。FPolicy 通过 SETATTR/GETATTR 生成 NFSv4.2 文件操作的通知，包括扩展属性写入（SETXATTR、REMOVEXATTR）和安全标签更改。NFSv4.2 通知需要使用 protobuf 格式配置的外部引擎。



 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-s3.html[对 S3 对象存储的 Fpolicy 支持]
 a| 
FPolicy 为 S3 对象工作流程提供安全监控。这为文件和对象存储提供了统一的 FPolicy 框架，简化了混合数据环境的安全操作。针对 S3 对象的 FPolicy 提供对象生命周期可见性，以监控对象的创建、删除和元数据标记更改，以满足安全性、合规性和审核要求。此功能提供无中断监控，而不会影响性能。

|===


[[nas]]
== NAS

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../smb-admin/supported-versions-functionality-concept.html[支持 Windows 客户端的 SMB 标准化名称查询]
 a| 
Windows 客户端可以在单个请求中检索规范的文件和目录名称，从而减少文件打开延迟并提高企业桌面、应用程序和文件服务器的 SMB 兼容性。ONTAP 自动返回打开的文件和目录的规范路径，避免在 Windows 11 24H2 及更高版本的客户端上进行逐组件查找，且无需进行额外配置。



 a| 
xref:../nfs-admin/support-vmware-vstorage-over-nfs-concept.html[VMware NFS 数据存储的自动空间回收]
 a| 
ONTAP 支持通过适用于 VMware VAAI 的 NetApp NFS 插件自动回收 NFS 数据存储的空间。当 VMware ESXi 9.0 或更高版本的主机发出 UNMAP 操作时，这有助于从精简配置的 VMDK 块范围中回收空间。



 a| 
xref:../volumes/cautions-increasing-maximum-directory-size-concept.html[ONTAP FlexVol 卷的最大目录大小]
 a| 
ONTAP 通过支持高达 4GB 的目录大小，提高了包含多达约 2500 万个文件的超大目录的性能。运行在单个目录中生成极高文件数量的工作负载（例如 AI 训练）的客户，可以通过避免以前在大型目录中出现的性能损失而受益。它还可以通过确保目录在数据保护故障转移后保持完全索引来提高弹性，因此即使 SnapMirror 关系中断，复制的副本也能表现良好。此功能适用于 AFF 和 FAS 存储系统（包括 MetroCluster 部署）；可以根据需要在每个卷上启用。



 a| 
xref:../task_nas_provide_client_access_with_name_services.html[自动 SID 到 UNIX ID 转换支持]
 a| 
ONTAP 为连接 LDAP 的 SVM 引入了自动 SID 到 UNIX ID 转换支持，以便从 Windows SID 生成和反向转换 POSIX UID/GID。这消除了在 Active Directory 中手动维护 uidNumber/gidNumber 属性的需要，减少了管理开销，并有助于确保跨 NFS 和 SMB 的一致文件访问。这一符合行业标准的功能对于从基于 SSSD 的 NAS 平台迁移大型网络并希望保持身份映射一致性的客户来说尤其有价值。默认情况下，该功能处于禁用状态，并按 SVM 进行配置。

[[san]]
== SAN

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../revert/remove-persistent-reservation-registrations.html[SCSI 永久预留注册规模扩大]
 a| 
每个 LUN 支持的最大 SCSI-3 永久保留注册数从 182 个增加到 256 个。这有助于大型群集 SAN 环境（例如 VMware 来宾群集和 Windows Server 故障转移群集）支持在共享 LUN 上进行更多主机注册，而无需更改永久保留管理工作流。



 a| 
SAN copy 卸载性能改进
 a| 
ONTAP 可提高符合条件的 NVMe 和 SCSI 拷贝工作负载的 SAN 拷贝卸载性能。请联系您的 NetApp 代表了解详细信息。



 a| 
xref:../svm-migrate/migrate-svm-task.html[支持从 ASA r2 系统到 ASA 或 AFF 系统的无中断存储 VM 迁移]
 a| 
您可以无中断地将存储虚拟机 (SVM) 从 2 节点 ASA r2 集群迁移到 2 节点 ASA 或 2 节点 AFF 集群。在迁移期间，将保留 LUN 和命名空间的现有主机映射和存储单元配置，从而减少操作工作量和风险。

== S3对象存储

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../s3-snapmirror/index.html#snapmirror-s3-requirements[MetroCluster 支持 SnapMirror S3]
 a| 
您可以创建 SnapMirror S3 关系，这些关系位于 MetroCluster 配置中，在切换和切回期间保持可用，并从活动站点恢复。



 a| 
xref:../s3-config/create-bucket-lifecycle-rule-task.html[MetroCluster 支持 ONTAP S3 存储桶生命周期管理]
 a| 
您可以在 MetroCluster 配置中为原生 S3 存储桶创建 ONTAP S3 存储桶生命周期管理规则。



 a| 
xref:../s3-config/create-s3-object-store-server-task.html[灵活的 S3 存储桶大小调整]
 a| 
ONTAP 支持新 S3 存储桶的可配置默认大小。这有助于减少应用程序在不指定容量的情况下通过 S3 API 创建存储桶时手动调整大小。如果未配置默认大小，存储桶创建行为将保持不变。

 a| 
xref:../s3-config/ontap-s3-supported-actions-reference.html[ONTAP S3 灵活校验和支持]
 a| 
ONTAP S3 支持 S3 NAS 存储桶的兼容 AWS 的 CRC-64NVME 校验和。当 S3 客户端为支持的上传和分段操作提供校验和信息时，ONTAP 会验证并存储校验和，并返回支持的 GET 和 HEAD 请求的校验和信息。

[[security]]
== 安全性

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
用于管理连接泛洪和预集群增强的 Apache 公平队列
 a| 
ONTAP 在管理 Web 服务器上引入了选择加入、默认关闭的源 IP 公平队列，以帮助在管理连接泛洪期间保持对 REST、System Manager 和 ONTAPI 的访问。ONTAP 还支持通过仅限集群前的 REST API 进行映像安装，并增强了动态主机配置协议（DHCP）处理，因此在节点等待集群设置时，集群前节点管理 LIF 在租约续订和 IP 地址更改期间仍保持可用。



 a| 
xref:../anti-ransomware/modify-snapshot-options-arpai.html[增强对 ARP/AI 快照响应策略的控制]
 a| 
您可以在 SVM 或卷级别配置 ARP/AI 快照响应策略，以控制 ARP/AI 在检测到异常活动时是否创建快照。有三种策略可用： `alert-with-proactive-and-periodic-snapshot`（默认，保留现有行为）、 `alert-with-proactive-snapshot`（仅攻击快照，无定期快照）和 `alert-only`（仅警报和事件日志，不创建快照）。升级到 9.20.1 后，默认定期快照最大计数从 6 更改为 2，默认保留期从 12 小时更改为 7 小时，除非之前已修改这些节点级别选项。



 a| 
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[数据 SVM 的密钥管理工作流程改进]
 a| 
当您在数据 SVM 上启用外部密钥管理器时，ONTAP 可以自动将该 SVM 的卷加密密钥从管理范围密钥管理器迁移到新的数据 SVM 密钥管理器。这简化了向外部密钥管理的过渡，并消除了在标准工作流程中单独进行手动迁移步骤的需要。



 a| 
xref:../multi-admin-verify/index.html[支持 IdP、AD 和 LDAP 组作为 MAV 审批人]
 a| 
MAV 审批组可以包括作为审批人的身份提供程序（IdP）、Active Directory（AD）和 LDAP（nsswitch）组以及单个管理员。支持的组类型包括 Entra ID、ADFS、AD 域组和 LDAP 组。在 IdP、AD 或 LDAP 目录中添加或删除用户不需要对 MAV 配置进行任何更改。对用户组成员身份的更改将在用户下次登录时重新进行身份验证后生效。您可以使用 security multi-admin-verify registered-operations show 命令显示当前集群上可用的所有 MAV 可保护操作。



 a| 
xref:../networking/configure_snmpv3_users_in_a_cluster.html[SNMPv3 SHA-512 身份验证支持]
 a| 
ONTAP 支持 SNMPv3 用户的 SHA-512 身份验证。此增强功能允许您将更强大的 SNMPv3 身份验证用于外部 SNMP 客户端和交换机监控，包括需要 SHA-512 身份验证的交换机。有关详细信息，请参见在 ONTAP 集群中配置 SNMPv3 用户和为以太网交换机健康监控配置 SNMPv3。

有关详细信息，请参见 https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["配置 SNMPv3 以进行以太网交换机运行状况监控"]。

[cols="30%,70%"]
|===

 a| 
xref:../concepts/capacity-measurements.html[简化存储效率数据缩减率报告]

存储效率数据减少率（DRR）通过仅包含可缩减数据来更精确地评估 ONTAP 存储效率节省的空间。在 ONTAP 9.19.1 及更早版本中，DRR 包括可缩减和不可缩减数据。

 a| 
自动重复数据删除调度程序（ADS）优化
 a| 
ONTAP 提高了 ADS（自动重复数据删除调度程序）性能，允许每个节点有更多的并发重复数据删除会话，以及更智能、更有针对性的限制，以更好地平衡客户端 I/O。DP 卷上的重复数据删除活动（来自 SnapMirror 传输）和全局重复数据删除会话与常规卷重复数据删除一起管理，从而减少竞争和元数据增长。您可以从存储效率节省中受益，特别是在混合工作负载下，无需更改配置。默认情况下，此功能处于启用状态，并且在 AFF 存储系统上可用。

[[storage-resource-management-enhancements]]
== 存储资源管理增强功能

[cols="30%,70%"]
|===
| 更新 | Description 


 a| 
xref:../s3-config/delete-recover-bucket-with-data-task.html[支持删除包含对象的 ONTAP S3 存储桶]
 a| 
使用可配置的基于保留的恢复窗口时，管理员可以计划删除包含对象的存储分段。这可以在保留窗口到期之前实现存储分段恢复。该功能减少了过期积压，并使容量更快地可供高数据变动率工作负载重新使用。



 a| 
xref:../flexcache/sizing-concept.html[FlexCache 大小限制增加]
 a| 
当每个 FlexCache 卷使用一个组成部分时，支持的卷数量增加到每个节点 2500 个，每个 HA 对增加到 5000 个。

您可以从原始卷创建的 FlexCache 卷数量增加到 200 个，每个原始卷的写回缓存数量增加到 50 个。



 a| 
xref:../flexcache/supported-unsupported-features-concept.html[NVFail 支持 FlexCache]
 a| 
您可以创建与启用了 NVFAIL 的源的 FlexCache 关系。您还可以独立于源卷在缓存卷上启用 NVFAIL。在已发生 NVFAIL 的源卷或缓存卷上，ONTAP 会阻止数据读取或修改，同时保留已修改缓存数据的回写，并在恢复后恢复正常 I/O。



 a| 
异步删除的性能增强
 a| 
ONTAP 增强了异步删除性能，加快了 NAS/SMB 客户端的空间回收。请联系您的 NetApp 代表了解详细信息。



 a| 
xref:../data-protection/calculate-reclaimable-space-task.html[支持计算 FlexGroup 卷上的可回收空间]
 a| 
ONTAP 支持在删除 FlexGroup 卷上的快照之前重新计算可回收空间。



 a| 
xref:../flexgroup/provision-automatically-task.html[自动配置高性能 FlexGroup 卷]
 a| 
ONTAP 通过存储配置文件简化了 FlexGroup 配置，让客户可以为其工作负载选择平衡或高性能的数据容器，从而减少了管理员为满足性能要求而手动配置和调整成分卷大小的需求。



 a| 
xref:../flexgroup/enable-adv-capacity-flexgroup-task.html[SMB 多通道支持与高级容量再平衡]
 a| 
ONTAP 支持在 FlexGroup 卷上启用高级容量平衡时使用 SMB 多通道。



 a| 
xref:../svm-migrate/index.html#supported-and-unsupported-features[支持 S3 NAS 存储桶的 SVM 迁移]
 a| 
ONTAP 支持对在 FlexVol 卷上托管 S3 NAS 存储桶的 SVM 进行 SVM 迁移，允许管理员迁移 SVM，而无需首先删除 S3 NAS 配置。



 a| 
xref:../task_nas_file_system_analytics_view.html[文件系统分析访问时间保存]
 a| 
文件系统分析扫描和 System Manager 文件系统资源管理器浏览会保留目录访问时间（atime）元数据。这有助于为归档、分层、合规性和数据生命周期工作流维护准确的 atime 值。



 a| 
xref:../volumes/manage-svm-capacity.html[MetroCluster IP 对 ONTAP SVM 容量限制的支持]
 a| 
您可以为属于 MetroCluster IP 配置一部分的 SVM 配置存储限制。



 a| 
FlexCache 卷指标
 a| 
FlexCache 卷指标报告 FlexCache 卷与其源卷之间交换的数据和元数据量。现有的 ONTAP REST 卷统计信息和指标端点中添加了两个新属性，这些属性提供了对 FlexCache 到源以及源到 FlexCache 数据传输的可见性。计数器会自动收集，无需配置；它们有助于容量规划、性能分析、网络故障排除和计费分析。此功能要求在 FlexCache 和源节点上均运行 ONTAP 9.20 或更高版本。有关详细信息，请参见 link:https://docs.netapp.com/us-en/ontap-automation["ONTAP 自动化"^] 文档。



 a| 
集群内再平衡
 a| 
ONTAP 引入了两种新的均衡放置功能，帮助在工作负载和集群容量不断演变时，以最少的管理工作量保持集群的最佳性能。配置时放置控制允许客户在通过 REST API 放置新卷时，指示应优先考虑性能还是空间要求。空间性能再平衡（SPR）是一个后台进程，它会不断寻找整个集群中正在形成的性能热点或聚合空间压力。根据配置的模式，SPR 要么通过 EMS 通知建议进行纠正性卷移动，要么使用标准且无中断的 ONTAP 卷移动操作自动执行移动。有关详细信息，请参阅 link:https://docs.netapp.com/us-en/ontap-automation["ONTAP 自动化"^] 文档。
